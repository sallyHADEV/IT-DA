# 잇다(IT-DA) 설계 정리

목표: UiPath를 참조하되 무거운 기능을 걷어낸 **경량 범용 매크로 도구**.
차별점은 하나다 — **타겟 프로그램의 상황(화면)을 먼저 인식하고, 동작에 필요한 화면이 아니면
스스로 그 화면으로 이동한 뒤 동작한다.**

---

## 1. 언어의 선택

| 후보 | 판단 |
|---|---|
| **Python 3.14 + PyQt6** ✅ | 채택. 환경에 PyQt6·OpenCV·NumPy·Pillow·PyAutoGUI·PyInstaller가 이미 있고, `QGraphicsView`가 플로우차트 에디터에 그대로 맞는다. 이미지 매칭·OCR 생태계가 가장 두껍다. 무거운 연산(템플릿 매칭)은 OpenCV의 C++ 구현이 담당하므로 파이썬 속도는 병목이 아니다. |
| C# + WPF | Win32 입력 주입은 가장 깔끔하지만 .NET SDK 설치가 필요하고 비전/OCR 연동 작업량이 크다. |
| Electron + TS | 플로우차트 UI는 화려하나 화면 캡처·입력 주입·이미지 매칭 전부 네이티브 애드온이 필요해 오히려 복잡해진다. |

**의존성 원칙**: Python 3.14는 최신이라 휠이 없는 패키지가 많다. 새 의존성을 늘리지 않는다.
화면 캡처도 `mss` 대신 PyQt6의 `QScreen.grabWindow`를 쓴다. 1차 구현에서 추가 설치는 **0개**.

대상 환경은 **Windows 데스크톱 + Windows 터치 주입**(`user32.InjectTouchInput`)으로 확정했다.
Android(ADB)는 범위 밖이지만, 입력 백엔드를 어댑터로 분리해 두어 나중에 붙일 수 있다.

## 3. 구현에 필요한 요소 정리

### 3.1 데이터 모델 (`itda/core/model.py`)

```
Project ─┬─ Flow ─┬─ Node ── Action*     노드 = 액션 시퀀스 컨테이너(= 모듈형 노드)
         │        └─ Edge                출구(ok/fail/true/false…) → 입구
         ├─ ObjectRepo ── TargetObject*  이름 + 태그 + 이미지 여러 장
         └─ StateGraph ─┬─ State*        상황 판정(조건 AND/OR 트리)
                        └─ Transition*   상황 이동(비용 + 이동 동작)
```

핵심 설계 두 가지:

* **노드가 모듈이다.** 노드 하나가 액션 여러 개를 품는다. 그래프는 흐름과 상황 조건만 표현하므로
  플로우차트가 잘게 부서지지 않는다. 플로우 파일 자체도 모듈이라 `subflow` 노드로 불러 쓴다.
* **상황이 1급 개념이다.** 노드에 `required_state`가 있고, 맞지 않으면
  `navigate | wait | skip | fail` 중 하나로 처리한다. `navigate`면 전이 그래프에서
  최소 비용 경로(`StateGraph.find_path`, 다익스트라)를 찾아 이동한 뒤 동작한다.

### 3.2 확장 규약 — 액션 추가에 UI 코드가 필요 없다

```python
@register_action
class Click(ActionType):
    ID = "click"; LABEL = "클릭"; CATEGORY = "입력"
    PARAMS = [Field("point", "point", "좌표"), Field("button", "enum", ...)]
    @classmethod
    def summary(cls, params): ...
```

이렇게 클래스 하나만 쓰면 팔레트 등록 · 속성 폼 자동 생성 · 저장/로드 · 요약 표시가 전부 따라온다.
(`itda/core/registry.py` + `itda/gui/widgets/schema_form.py`)

지원 필드 타입: int, float, str, text, bool, enum, point, rect, color, key, var, expr, file,
object_ref, object_ref_list, flow_ref, state_ref, node_ref, point_list.
`depends_on`으로 조건부 표시(예: 반복 방식이 "지정 횟수"일 때만 횟수 칸)를 지원한다.

### 3.3 동작 (액션) 목록

| 분류 | 액션 |
|---|---|
| 인식 | 이미지 찾기(다중 이미지 any/best/all) · 이미지 대기 · OCR(한/영/숫자) · 픽셀 색 확인 |
| 입력 | 클릭 · 이동 · 드래그 · 휠 · 키 입력 · 문자 입력 · 터치 · 멀티터치(핀치/회전) · 터치 드래그 |
| 흐름 | 대기 · 조건 · 플로우 실행 · 상황으로 이동 · 상황 대기 · 중단 |
| 데이터 | 변수 지정 · 연산 · 클립보드 · 로그 |
| 도구 | 경고음 · 스크린샷 · 창 제어 · 프로그램 실행 |

노드 종류: 시작 · 동작 · 분기 · 다중 분기 · 반복 · 플로우 호출 · 상황 이동 ·
**창 맞추기** · 종료 · 메모.

#### 창 맞추기 — 재현성의 출발점

창 크기가 실행할 때마다 다르면 안의 버튼 위치도 달라져 좌표와 이미지 검색 범위가 전부 어긋난다.
그래서 보통 플로우 맨 앞에 창을 정해진 자리·크기로 맞추는 단계를 둔다. 노드(`창 맞추기`)와
액션(`창 제어`)이 같은 파라미터를 쓴다.

* 동작: 앞으로 가져오기 / 위치·크기 지정 / 위치만 / 크기만 / 화면에 맞춰 배치 /
  최대화 · 최소화 · 복원 / 항상 위 / 닫기 / 존재 확인
* 배치 프리셋: 가운데, 모니터 채우기, 좌·우·상·하 절반, 사분면 4종
* 기준 모니터: 창이 있는 모니터 / 주 모니터 / 번호 지정
* 크기에 `0` 을 넣으면 그 축은 현재 값을 유지한다(가로만 고정하고 싶을 때)
* 계산 결과는 항상 모니터 안으로 밀어 넣어 제목 표시줄을 잃지 않게 한다

#### 이미지 찾기 vs 이미지 대기

둘은 목적이 다르다.

| | **이미지 찾기** | **이미지 대기** |
|---|---|---|
| 목적 | 지금 화면에서 **좌표를 얻는다** | 화면이 바뀔 때까지 **기다린다** |
| 결과 | `[x, y]` 좌표 (+ 최근 위치 기억) | 성공/실패(참·거짓) |
| 못 찾으면 | 즉시 실패 (`못 찾으면 재시도`를 주면 그동안만 재시도) | 제한시간까지 계속 확인 |
| 사라짐 | 못 한다 | **할 수 있다** ("사라질 때까지") |
| 쓰는 곳 | 클릭할 자리를 찾을 때 | 창이 뜨기를/로딩이 끝나기를 기다릴 때 |

전형적인 조합은 `이미지 대기(창이 뜰 때까지)` → `이미지 찾기(버튼 좌표)` → `클릭` 이다.
대기만으로 충분한 경우가 많아서, 대기에도 "찾은 좌표도 기억" 옵션을 두어 뒤따르는 클릭이
다시 찾지 않게 할 수 있다.

#### 찾은 좌표는 어떻게 이어지나 — 최근 찾은 위치(match cache)

실행 중에는 **객체별 '최근 찾은 위치'** 가 유지된다. `이미지 찾기`가 이 값을 채우고,
클릭·이동·드래그·터치가 이 값을 읽는다. 캐시 수명은 **플로우 한 번 실행**이다
(같은 객체를 다시 찾으면 갱신된다).

좌표를 넘기는 방법은 두 가지다.

1. **객체로 지정** (권장) — 클릭의 `위치 지정 = 객체 위치`, `객체 위치` 옵션으로 정한다.
   * `최근 찾은 위치 사용 (없으면 새로 찾기)` — **기본값.** 앞에 이미지 찾기가 있으면 **다시 찾지 않는다.**
     찾기 없이 클릭만 두어도 그 자리에서 한 번 찾으므로 그냥 동작한다.
   * `항상 새로 찾기` — 목록이 스크롤되는 등 화면이 움직일 때.
   * `최근 찾은 위치만 사용` — 반드시 앞의 찾기 결과를 쓰게 강제(없으면 실패). 매칭 비용을 통제할 때.
2. **변수로 넘기기** — 이미지 찾기의 `결과를 담을 변수`에 `[x, y]` 가 담긴다.
   파생 변수 `<이름>_x`, `<이름>_y`, `<이름>_ok` 도 함께 생기므로 식에서 쓰기 좋다
   (예: `찾은위치_x > 800`). 클릭에서 `위치 지정 = 변수의 좌표` 로 그 변수를 고르면 된다.
   좌표를 계산해서 옮기거나(오프셋), 다른 노드·플로우로 전달할 때 쓴다.

데모 재생(F5)은 이 규칙을 그대로 흉내 내어 로그에 "최근 찾은 위치를 재사용합니다 / 다시 찾습니다"
를 남긴다. 플로우를 짜면서 어디서 매칭이 다시 일어나는지 눈으로 확인할 수 있다.

### 3.4 시간·좌표 허용오차 (변동계수)

`TimingProfile`(프로젝트 전역)을 노드·액션이 **상속**한다.

* 전체 적용: 타이밍 프로파일 대화상자에서 값 하나를 바꾸면 상속 중인 모든 동작이 함께 바뀐다.
* 개별 제어: 해당 노드/액션에서 "상속" 체크를 끄면 자기 값을 쓴다.
* 항목: 딜레이 배율, 시간 변동계수(±%), 좌표 허용오차(px), 이동 시간, 매칭 임계값, 기본 선/후 딜레이.

### 3.5 예외 처리

노드마다 재시도(횟수·간격)와 에러 정책을 둔다:
`실패 출구로 진행 | 지정 노드로 이동 | 무시하고 계속 | 플로우 중단 | 상위로 전달`,
추가로 경고음·화면 저장·로그 메시지.

### 3.6 작업 도구

| 도구 | 내용 |
|---|---|
| 좌표 도구 | 화면을 얼린 뒤 8배 확대경으로 픽셀 단위 지정. 방향키 미세조정, 좌표+RGB 표시. |
| 스크린샷 도구 | 드래그로 영역 지정 → 좌표와 이미지를 함께 반환(객체 저장 / 검색 범위 지정 겸용). |
| 객체화 도구 | 스크린샷을 MSER + 적응형 이진화/에지 윤곽으로 자동 분할 → 아이콘·글자·버튼 후보 제시 → 다중 선택 → **일괄 개별 PNG 저장 + 객체 등록**(이름 접두사·태그·여백 지정, Ctrl+드래그로 수동 박스 추가). |

### 3.7 실행 시각화 계약

실행 엔진은 GUI를 모른다. `itda/core/events.py`의 이벤트 버스에 다음만 발행한다.

```
node_status(flow, node_id, idle|pending|running|ok|fail|skipped|break)
edge_fired(flow, edge_id)          action_status(flow, node, action, status)
variables(flow, {이름: 값})         state_detected(state_id, 이름)
flow_running(flow, bool)           logged(LogRecord)
```

1차에서는 `itda/engine/demo.py`(데모 재생기)가 이 이벤트를 흘려 시각화 경로를 완성해 두었다.
2차 실행 엔진은 같은 이벤트만 쏘면 GUI 수정 없이 그대로 붙는다.

### 3.8 파일 포맷

프로젝트 = 폴더 하나. 전부 JSON + PNG이므로 탐색기에서 플로우 파일을 복사해 다른 프로젝트에
붙여 넣으면 그대로 모듈이 된다.

```
MyProject/ project.json  flows/*.flow.json  objects/objects.json  objects/img/*.png  states/states.json
```

읽을 때 없는 키는 기본값으로 채우고 모르는 키는 버린다(`itda/core/serde.py`) — 버전이 달라도 열린다.

### 3.5 사람처럼 움직이기 (`itda/core/humanize.py`)

기계가 만든 입력은 직선·일정 속도라 탐지되기 쉽다. 궤적과 시간을 흐트러뜨리는 항목을 각각
스위치로 켜고 끈다: 곡선 궤적(3차 베지에) · 가속/감속 · 오버슈트 · 미세 정지 · 타이핑 리듬 ·
클릭 시간 변화 · 대기 중 드리프트. 편집기의 미리보기는 실제 생성 함수를 호출하므로
**화면에 보이는 궤적이 실행될 궤적**이다. 액션마다 프로파일을 따르거나 개별로 끌 수 있다.

2차 입력 주입부는 좌표와 시간을 반드시 이 모듈을 통해 만든다.

## 4. 2차 작업 (실행 엔진)

상세 계획: [2차-개발-계획.md](2차-개발-계획.md)

1. **입력 주입**: 마우스·키보드(SendInput), 터치(`InjectTouchInput`, 멀티포인트/드래그)
2. **비전**: 멀티스케일·다중 이미지 템플릿 매칭, 검색 범위 한정,
   **최근 찾은 위치 캐시**(위 3.3 규칙대로 `cache_or_search / always / cache_only` 처리)
3. **OCR**: `OcrBackend` 인터페이스 + Tesseract(kor+eng) 구현, 전처리(확대·이진화)
4. **상황 워처**: 주기 캡처 → 조건 트리 평가 → 현재 상황 판정 → `state_detected` 발행
