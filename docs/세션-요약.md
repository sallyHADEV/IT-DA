# 세션 요약 — 잇다(IT-DA) 개발 기록

## 프로젝트 개요

**잇다(IT-DA)** — UiPath를 참조했지만 더 가벼운, 상황 인식형 범용 매크로 도구.
핵심 차별점: *타겟 프로그램의 "상황"을 먼저 인식하고, 필요한 화면이 아니면 스스로 이동한 뒤 동작한다.*

- **스택**: Python 3.14 + PyQt6, Windows 데스크톱 전용
- **디자인**: 딥 네이비 + 코럴 플랫 UI, 색상은 `style.py`에만
- **아키텍처 원칙**: 스키마 기반 자동 폼 생성(`Field` 목록만 선언하면 UI 코드 불필요), 계획(pure)과 실행(부작용) 분리, 이벤트 버스로만 GUI 갱신

1차(에디터)·2차(실행 엔진) 개발이 모두 완료된 상태에서 이번 세션이 이어졌다.

## 이번 세션에서 다룬 것

### 1. 노드 편집 창의 흰 화면 깜빡임 + 좌표 도구 먹통

**증상**: 노드 편집 창(모달)에서 좌표 도구를 열면 커서를 따라오지 않고, 좌표를 클릭하면 편집 창이 닫혀 버렸다.

**원인 2개, 함정 1개**:
- 오버레이가 모달이 아니어서 위의 모달 대화상자가 이벤트를 가로챔 → `ApplicationModal`로 수정
- **최초 수정이 더 큰 버그를 만들 뻔함**: 대화상자를 `hide()`로 치우려 했는데, `QDialog`는 감춰지는 순간 `exec()` 루프가 끝난다는 걸 실측으로 발견. `setWindowOpacity(0)`으로 변경(캡처에서는 사라지되 창은 살아 있음, 78/78 → 0/78 픽셀로 확인)
- 부모 창만 숨기면 자식 대화상자는 그대로 남는다는 사실도 실측으로 확인

### 2. 코드 리뷰 대응 (2회)

**1차 리뷰 — Critical 1건 + Important 4건**
- **실행 중 GUI 조작으로 인한 모델 훼손**: `RunController._tick()`이 `processEvents()`를 부르는데, 그 틈에 노드 삭제 등이 가능했음. `set_editing_locked()` 추가 — 캔버스는 비활성화 대신 선택/드래그/드롭만 막고 줌/팬은 유지, 모달 대화상자를 여는 모든 동작 잠금, 실행 중 창 닫기는 정지 신호만 보내고 무시
- `NodeRefEditor.refresh_choices()`에 예외 노드 유지 로직 누락 → 통합
- `ObjectPanel`의 비공개 메서드 직접 호출 → `object_updated()` 공개 메서드로 캡슐화
- 임시 파일 삭제가 예외 시 스킵될 수 있음 → `try/finally`
- `PointListEditor`가 파싱 실패 시 좌표를 지워버림 → 줄마다 마지막 성립값 보관, 실패 시 빨간색 표시만

**2차 리뷰 — GDI/동시성/스레드 안전성**
- **GDI 핸들 누수 의심**: 실측 결과 이 머신(Win11 x64)에서는 `DeleteDC`가 지연 삭제를 마무리해 실제로 새지 않음(문서화된 동작 아님, 다른 환경에선 샐 수 있어 정석대로 수정: `SelectObject`로 되돌린 뒤 삭제)
- **64비트 truncation 의심**: 이 환경에선 핸들 값이 항상 32비트 안에 들어 재현 안 됨. 그래도 `restype`/`argtypes` 명시(정석)
- **InputArbiter 재진입 TOCTOU**: 실제 존재하는 버그. 스레드 스트레스로는 재현 안 됨(GIL) → 문제였던 순서를 결정론적으로 재현해 검증. `_acquire()`로 판정+획득을 원자화
- **작업 스레드의 Qt GUI API 호출**: `screenshot` 액션이 항상 Qt 전용 캡처를 쓰고 있었음(더 심각) → `capture.grab_array()`(GDI, 스레드 안전) + `on_gui_thread()` 가드로 수정

### 3. UI/UX 기능 추가

- **창 위치·크기·이름 가져오기 도구**: 스크린샷 도구처럼 화면 위 창에 호버하면 빨간 테두리, 클릭하면 그 창 정보를 가져와 창 맞추기 노드의 제목/좌표/크기 4칸을 한 번에 채움(`beginMacro`로 undo 1회로 묶음)
  - 재현 리뷰에서 5건 추가 발견: 우리 프로세스 창을 프로세스 단위로 걸러야 함(핸들만 거르면 투명해진 대화상자가 여전히 걸림), 방향키로 커서 이동 시 강조가 안 따라옴, 기본값 라벨이 하드코딩(88%)이라 프로파일 변경을 반영 못함, 버튼이 도구 미주입 시 비활성화 안 됨
- **일치 임계값을 슬라이더로**: 숫자 스핀박스 대신 "불일치 허용 ↔ 정확히 일치" 슬라이더 + "기본값 사용(N%)" 체크박스. 0=상속이라는 특수 의미를 체크박스로 분리
- **캔버스 화면 이동(패닝)**: 가운데 버튼 드래그 + Alt/Shift+좌드래그. 플로우 캔버스와 시퀀스 뷰에 중복 구현돼 있던 것을 `PanMixin`으로 통합
- **객체 패널 가독성**: 썸네일 26×20→56×30, 격자 칸을 넓혀 이름이 두 줄로 온전히 보이게. 예외 이미지 장수(`·2장`)와 "이미지 없음" 상태를 표시. 사용자 피드백으로 "격자를 버리고 리스트로" 초안을 두 번 조정(리스트는 14개→2개로 밀도가 너무 떨어짐 → 넓은 격자로 절충, 6개 확보)

### 4. 실행 속도 최적화 (측정 기반)

| 항목 | 전 | 후 |
|---|---|---|
| 검색 범위 지정 시 화면 캡처 | 131.6ms (전체 9.1M픽셀) | **8.2ms** (해당 영역만) |
| OCR `tesseract_path()` 매 호출 | 6.34ms | **0ms** (캐시) |

- **위험 지점은 좌표**였음: 조각 기준 결과를 화면 좌표로 되돌리고, 힌트는 반대로 조각 기준으로 변환. ROI가 (0,0)에서 시작하는 경계 경우도 검증
- **OCR 본체는 못 고침**: 비용의 95%가 tesseract 프로세스 기동+모델 적재. `OMP_THREAD_LIMIT=1`, `--oem 1` 실측했으나 효과 없음(추측 적용했으면 오판할 뻔함)

### 5. OCR 엔진 대안 조사

Python 3.14 휠 유무를 `--only-binary=:all:`로 정확히 확인(dry-run은 신뢰 불가 — 실제로 `winsdk`가 dry-run에서는 "가능"으로 나왔지만 실제 설치는 빌드 실패).

**결론**: 이 PC에 이미 설치된 **Windows 내장 OCR**(`winrt-Windows.Media.Ocr`)이 한국어를 지원하며, Tesseract 대비 **약 25배 빠름**(3.8~6.1ms vs 127~166ms)이고 정확도도 동등 이상(쉼표 등 일부는 더 나음). in-process라 프로세스 기동 비용이 없는 게 핵심.

### 6. 실제 버그 리포트 대응 — `TypeError: 'NoneType' object cannot be interpreted as an integer`

**클릭이 전부 이 오류로 실패하고 있었음.** 원인: `Win32Sender`의 `INPUT` 구조체 `dwExtraInfo` 필드(`ULONG_PTR` = 정수 타입)에 `None`을 넣고 있었음. 마우스·키보드 양쪽 다.

**더 중요한 발견**: 이 경로는 **테스트가 한 번도 밟은 적이 없었다.** `conftest.py`의 안전장치(`Win32Sender.apply` 차단)가 실제 마우스 오작동은 막았지만, 그 대가로 실주입 코드 자체가 완전한 사각지대가 됐다. `SendInput`(시스템콜)만 가짜로 바꾸고 구조체 조립은 진짜로 시키는 테스트 11개를 신설(`test_win32_sender.py`)해서 메웠다.

### 7. 사용자 지적 2건 (매크로 동작 관찰)

- **스크린샷 도구가 드래그 중 확대경을 감춤**: 정확도가 가장 필요한 순간(끝나는 모서리 맞추기)에 정보가 없어짐. 드래그 중에도 확대경+십자선 유지, 끄는 크기를 옆에 표시
- **드래그·스크롤 시작이 순간이동**: "사람처럼 움직이기"가 목적지 이동에만 걸려 있고, 시작점까지 가는 길은 텔레포트였음(실측: 첫 이동 1274px 점프 → 2px로 수정). 목적지는 정확히, 가는 길만 사람처럼(허용오차는 안 흔듦)

## 확립된 작업 방식

1. **모든 수정은 되돌려서 테스트가 실제로 실패하는지 확인한다.** 이번 세션에서 "통과했지만 아무것도 증명 못 하는 테스트"가 최소 3번 나왔다(뷰 대신 view로 이벤트를 보내 핸들러 자체에 도달 못한 경우, 테마 미적용으로 버튼 폭이 실제와 다르게 측정된 경우, `arbiter.owner`만 읽어 회수 로직을 안 거친 경우). 매번 원인을 찾아 테스트를 다시 썼다.
2. **추측 대신 측정한다.** 성능·타이밍·픽셀 단위 UI 확인 모두 스크립트로 실측했고, 렌더링해서 스크린샷으로 눈으로 확인했다.
3. **환경에서 재현 안 되는 것은 안 된다고 솔직히 적는다.** GDI 누수, 64비트 truncation 등은 "이 머신에서는 재현 안 됐지만 정석이라 고쳤다"고 구분해서 기록했다.
4. `docs/2차-개발-계획.md`에 매 항목을 완료 표시와 함께 근거·실측치를 남겼다.
5. 마지막에 **다른 AI에게 넘길 테스트 작성 지침**(`docs/테스트-지침-프롬프트.md`)을 만들어, 이번에 밟은 함정들(Qt viewport, 테마 적용, GIL 경합, 단색 이미지 매칭 등)을 재사용 가능한 규칙으로 남겼다.

**637개 통과** (세션 시작 시점 대비 다수 증가 — 이번 세션에서만 회귀 테스트를 70개 이상 추가).

## 남은 것 / 판단이 필요한 것

- 창을 1100px 아래로 줄이면 도구모음에서 **실행 정지** 버튼이 넘침 메뉴에 숨음 — 배치 변경이 필요해 임의로 하지 않음
- 객체 패널의 편집 폼이 도크의 상당 부분을 차지함 — 선택 없을 때 접는 개선안 제시했으나 미착수
- Windows 내장 OCR 백엔드 추가는 조사만 완료, 실제 통합은 미착수(검증용으로 `winrt-Windows.*` 패키지 몇 개 설치됨 — 필요 없으면 제거 필요)
- `dist/` 배포본은 최신 코드 반영 안 됨(재빌드 필요 시 `python tools/build.py`)
