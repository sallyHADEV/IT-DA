# 잇다 (IT-DA)

플로우차트 기반 경량 범용 매크로 도구.

UiPath를 참조하되 무거운 기능을 걷어내고, **"타겟 프로그램의 상황(화면)을 먼저 인식하고,
동작에 필요한 화면이 아니면 스스로 그 화면으로 이동한 뒤 동작한다"** 는 한 가지 개념을 중심에 둔다.

## 실행

```bash
python -m itda
```

프로젝트 폴더를 바로 열려면: `python -m itda C:\경로\내프로젝트`

### 매크로를 실제로 돌리기

1. **플로우를 만든다** — 팔레트에서 노드를 끌어다 놓고 연결한다.
   보통 첫 노드는 `창 맞추기`(대상 창을 정해진 크기로 고정 → 좌표가 어긋나지 않는다).
2. **타겟을 객체로 저장한다** — `F3` 스크린샷 도구로 하나씩, 또는 `F4` 객체화 도구로 한꺼번에.
3. **`F8` 검사** — 없는 객체·플로우 참조, 순환 호출 같은 문제를 미리 잡는다.
4. **`F5` 데모 재생** — 실제 입력 없이 흐름과 계획(좌표·궤적·소요시간)을 로그로 확인한다.
5. **`F9` 실제 실행** — 확인 창이 한 번 뜬 뒤 진짜 마우스·키보드로 동작한다.

> **멈추는 방법: `F12`.** 잇다 창이 뒤에 있어도 동작하는 전역 단축키다.
> 매크로가 마우스를 잡고 있으면 정지 버튼을 누르기 어려우므로 이쪽을 기억해 두는 편이 좋다.

**`F10` 멀티 플로우 실행** — '자동 시작'으로 표시한 플로우들을 동시에 돌린다. 하나뿐인
마우스·키보드는 우선순위가 높은 플로우가 먼저 쓰고, 노드 단위로 넘겨받는다.

OCR 은 [Tesseract](https://github.com/UB-Mannheim/tesseract) 설치가 필요하다(한국어 데이터 포함).
설치돼 있으면 자동으로 찾고, 없으면 로그에 안내가 남는다.

### 상황이 바뀌어도 알아서 찾아가게 하려면

1. `F6` 상황 관리에서 화면마다 이름과 판정 조건을 등록한다(예: `메인화면`, `설정창`).
2. 화면 사이 **전이**를 등록한다 — "메인화면에서 톱니바퀴를 클릭하면 설정창" 같은 이동 동작.
3. 노드의 **필요 상황**에 `설정창` 을 지정한다. 실행할 때 다른 화면이면 엔진이 경로를 찾아
   스스로 이동한 뒤 동작한다.
4. 광고·업데이트 팝업처럼 아무 때나 뜨는 화면은 **'끼어드는 화면' 스위치**를 켜고 닫는 전이를
   등록한다. 실행 중 그 화면이 뜨면 하던 일을 멈추고 닫은 뒤 원래 목표로 돌아간다.
5. **`F11` 상황 감시**를 켜면 지금 화면이 어떤 상황으로 판별되는지 아래 '실행 상태' 에
   실시간으로 뜬다. 대상 프로그램의 화면을 옮겨 다니며 조건이 제대로 걸렸는지 바로 확인할 수
   있다. 실행할 때는 자동으로 켜진다.

## 배포 (실행 파일 만들기)

```bash
python tools/build.py
```

아이콘 생성 → PyInstaller 빌드 → **실제로 실행해 자체 점검**까지 한 번에 한다.
결과는 `dist/itda` 폴더이며, 통째로 압축해 넘기면 파이썬 없이 실행된다.

* `itda.exe` — 평소 쓰는 창 프로그램
* `itda-check.exe --selftest` — 콘솔 판. 빌드가 온전한지 확인할 때 쓴다
  (창 프로그램은 stdout 이 없어 출력이 보이지 않는다)

OCR 을 쓰려면 대상 PC 에도 Tesseract 설치가 필요하다 — 언어 데이터까지 묶으면 수백 MB 라
번들에 넣지 않았다.

## 화면 구성

| 영역 | 내용 |
|---|---|
| 가운데 | 플로우차트 캔버스 (탭으로 여러 플로우 동시 편집) |
| 왼쪽 | 프로젝트(플로우 목록) / 팔레트(노드·액션) / 객체 저장소 |
| 오른쪽 | 노드 액션 목록 / 속성(스키마 자동 생성 폼) |
| 아래 | 로그 / 실행 상태(현재 상황 배지 + 변수 워치) |

단축키: `F2` 좌표 도구 · `F3` 스크린샷 도구 · `F4` 객체화 도구 · `F5` 데모 재생 ·
`F6` 상황 관리 · `F7` 타이밍 프로파일 · `F8` 검사 · `Ctrl+L` 자동 정렬 · `Ctrl+0` 전체 보기

## 기능 (1차 = 에디터)

- **플로우차트** — 노드 드래그·포트 연결·박스 선택·줌/팬·격자 스냅·자동 정렬·되돌리기
- **모듈형 노드** — 노드 하나가 액션 시퀀스를 품는다. 플로우 파일 자체도 `플로우 호출` 노드로 재사용
- **상황(State)** — 화면마다 이름을 붙이고 판정 조건(AND/OR 트리)과 이동 방법(전이)을 등록.
  노드는 "이 동작은 설정창에서만" 이라고 선언만 하면 된다
- **객체화** — 타겟을 이름·태그로 분류하고 이미지를 여러 장 등록(예외 상황 대비)
- **창 맞추기** — 대상 창을 정해진 위치·크기로 고정(프리셋·모니터 지정). 창 크기가 매번 다르면
  좌표가 어긋나므로, 플로우 첫 단계로 두면 재현성이 확보된다
- **작업 도구** — 확대경 좌표 도구, 영역 스크린샷, **객체화 도구**(스크린샷을 아이콘·버튼·글자로
  자동 분할 → 골라서 일괄 저장)
- **타이밍/허용오차** — 딜레이·변동계수·좌표 오차를 프로파일로 전체 적용, 필요한 곳만 개별 지정
- **사람처럼 움직이기** — 곡선 궤적·가속/감속·오버슈트·타이핑 리듬을 스위치로 켜고 끄며,
  옆의 미리보기가 실제로 실행될 궤적을 그려 준다 (`F7`)
- **예외 처리** — 노드별 재시도와 에러 정책(실패 출구/지정 노드 이동/무시/중단/상위 전달)
- **멀티 플로우** — 동시에 실행할 플로우와 우선순위 설정
- **실행 시각화** — 진행 중인 노드·연결을 캔버스에 표시. 엔진이 없는 지금은 **데모 재생(F5)** 으로
  실제 입력 없이 흐름을 확인한다

## 구조

| 경로 | 역할 |
|---|---|
| `itda/core/` | 데이터 모델, 프로젝트 IO, 파라미터 스키마, 레지스트리, 변수, 타이밍, 이벤트 버스 |
| `itda/actions/` | 액션 타입 정의(파라미터 스키마 + 실행부) |
| `itda/vision/` | 화면 캡처, 자동 영역 분할 (매칭·OCR은 2차) |
| `itda/engine/` | 데모 재생기 (실행 엔진은 2차) |
| `itda/gui/` | 메인 윈도우, 캔버스, 패널, 대화상자, 작업 도구 |

설계 근거는 [docs/설계.md](docs/설계.md), 2차(실행 엔진) 계획은
[docs/2차-개발-계획.md](docs/2차-개발-계획.md) 참고.

### 액션 추가하기

클래스 하나만 등록하면 팔레트·속성 폼·저장/로드가 전부 따라온다. GUI 코드는 건드리지 않는다.

```python
@register_action
class MyAction(ActionType):
    ID = "my_action"
    LABEL = "내 동작"
    CATEGORY = "입력"
    PARAMS = [Field("count", "int", "횟수", 1, minimum=1, maximum=99)]

    @classmethod
    def summary(cls, params):
        return f"내 동작 {params['count']}회"
```

## 프로젝트 파일 포맷

프로젝트는 폴더 하나이며 내용은 전부 JSON + PNG다. 플로우 파일을 복사해 다른 프로젝트에
붙여 넣으면 그대로 모듈이 된다.

```
MyProject/
  project.json          타이밍 프로파일, 엔트리 플로우/우선순위, 전역 변수
  flows/*.flow.json     플로우 하나 = 파일 하나
  objects/objects.json  타겟 객체 (이름/태그/이미지 목록/매칭 옵션)
  objects/img/*.png
  states/states.json    상황 정의 + 전이 그래프 + 워처 설정
```
